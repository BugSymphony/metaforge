## Clarifications

### Session 2026-08-01

- Q: MVP 阶段 CLI 访问服务端的认证机制？ → A: 无认证（MVP 直连服务端，不实现传输层认证，凭据不得硬编码）
- Q: 端到端可验收性能目标如何设定？ → A: 端到端目标沿用服务端预算（task-brief ≤500ms、step-guide ≤150ms），CLI 侧开销占端到端比例 <5%
- Q: 配置文件的位置与机制如何确定？ → A: 默认零配置；配置文件位于用户目录（`~/.config/metaforge/config.yml`），环境变量（`META_FORGE_*`）优先级更高
- Q: 对瞬时故障是否自动重试？ → A: 有限自动重试 1 次（覆盖网络错误、上游不可用、视角超时），仍失败则给出人类可读提示

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Agent 获取任务认知简报 (Priority: P1)

执行任务前，Agent 需要先理解"这个任务是什么、有哪些规则、流程、能力与决策"。Agent 以自然语言描述目标任务，系统将意图转换为结构化查询，向服务端获取任务认知简报，并直接交付给 Agent 使用。

**Why this priority**: 任务认知是 MetaForge 指导 Agent"认知 → 决策 → 执行"的基础场景，也是实体指导、子任务收窄等其他能力的认知前提；自然语言到结构化参数的转换是本产品区别于直接调用服务端的核心职责，必须先打通。

**Independent Test**: 可独立验证——Agent 以自然语言描述一个目标任务（如"我想了解订单处理任务的规则与流程"），系统返回包含约束、流程、能力、决策分支的认知简报，内容可直接注入 Agent 上下文使用。

**Acceptance Scenarios**:

1. **Given** 服务端已注册任务认知模板且存在已发布 Bundle，**When** Agent 以自然语言描述目标任务，**Then** 系统返回结构化认知简报，包含约束级别、流程步骤、可用能力与决策分支，且全程未向服务端发送任何自然语言文本
2. **Given** 描述存在多个候选匹配项，**When** Agent 的描述无法唯一确定目标，**Then** 系统列出候选（含标识、名称、说明）请用户选择，不擅自猜测
3. **Given** 描述无任何匹配项，**When** 推测结果为零命中，**Then** 系统终止执行，说明未匹配原因并列出平台当前可用的候选选项
4. **Given** 服务端不可达或返回失败错误码，**When** 调用失败，**Then** 系统给出人类可读的简体中文提示，不暴露原始技术细节

---

### User Story 2 - Agent 执行中获取实体即时指导 (Priority: P1)

执行到某个具体步骤时，Agent 需要即时知道"这一步该怎么做、有什么约束与边界"。Agent 指定一个实体（步骤），系统返回该实体的约束级别、能力协议、决策分支、影响范围与相邻上下文。

**Why this priority**: 实体级指导是执行阶段最高频的即时认知诉求，直接支撑单步决策的正确性，价值密度高且可独立交付。

**Independent Test**: 可独立验证——Agent 指定一个已发布 Bundle 内的实体，系统返回该实体的约束、能力协议、决策分支与影响范围；缺失实体信息时给出用法提示。

**Acceptance Scenarios**:

1. **Given** 指定实体属于已发布 Bundle，**When** Agent 请求实体即时指导，**Then** 返回该实体的约束级别、能力协议、决策分支、影响范围与相邻上下文
2. **Given** 未提供实体信息，**When** Agent 发起实体指导请求，**Then** 系统提示必填用法说明并中止执行
3. **Given** 指定实体不属于任何已发布 Bundle，**When** 归属校验失败，**Then** 系统终止执行并展示候选列表供参考

---

### User Story 3 - 探索型 Agent 发现平台与领域 (Priority: P2)

初入平台或新领域的 Agent 需要先摸清"平台上有哪些可用库、这个领域里有什么、怎么逐层下钻"。Agent 请求平台清单，随后沿领域层级逐层下钻，获取可继续探索的路径。

**Why this priority**: 平台发现与领域导航是探索型 Agent 的入口能力，为后续精准查询提供寻址基础；分层下钻与分页续翻可独立验证，价值中等。

**Independent Test**: 可独立验证——Agent 请求平台资源清单，随后选择一个主题域逐层下钻，每次返回可继续探索的入口；结果集超过单页时可通过续翻完整遍历。

**Acceptance Scenarios**:

1. **Given** 平台存在已发布 Bundle，**When** Agent 请求平台清单，**Then** 返回 Bundle 列表、各 Bundle 版本信息与主题域概要
2. **Given** Agent 选中某主题域，**When** 请求逐层下钻，**Then** 返回层级结构、是否有更多内容与可继续下钻的入口
3. **Given** 结果集超过单页大小，**When** Agent 请求下一页，**Then** 系统基于游标续翻返回后续结果，直至完整遍历全部数据
4. **Given** 领域导航请求未指定任何范围，**When** Agent 发起请求，**Then** 系统提示必填用法说明并中止执行

---

### User Story 4 - 编排型父 Agent 委派子任务认知 (Priority: P2)

编排型父 Agent 委派子任务时，需要给子 Agent 一份收窄到其职责范围的认知简报，保证子 Agent 只接触该知道的内容。父 Agent 指定入口实体与收窄模式，系统返回收窄后的约束、能力、决策与可见范围清单。

**Why this priority**: 子任务收窄实现"职责隔离执行"，是编排场景的差异化能力，支撑多 Agent 协同，可独立验证。

**Independent Test**: 可独立验证——父 Agent 指定入口实体与收窄模式，系统返回收窄到该实体职责范围的简报与收窄范围清单；纯净模式下仅返回实体自身维度。

**Acceptance Scenarios**:

1. **Given** 指定入口实体与继承收窄模式，**When** 父 Agent 请求子任务简报，**Then** 返回收窄到该实体职责范围的约束、能力、决策以及收窄后的可见范围清单
2. **Given** 指定纯净模式，**When** 父 Agent 请求子任务简报，**Then** 仅返回实体自身维度的内容，不包含继承或扩散的内容
3. **Given** 未提供 Bundle 与入口实体，**When** Agent 发起子任务请求，**Then** 系统提示必填用法说明并中止执行

---

### User Story 5 - Agent 定制自由视角组合查询 (Priority: P2)

面对预置模板未覆盖的具体问题，Agent 需要按需组合若干认知视角，获得恰好符合其问题的聚合认知。Agent 指定所需视角子集与目标范围，系统返回对应章节的聚合结果。

**Why this priority**: 自由视角组合体现了"能力优先"的完备性，预置模板之外的定制诉求均由该能力承载，是模板驱动设计的关键验证点。

**Independent Test**: 可独立验证——Agent 指定任意视角子集与目标范围，系统返回恰好包含所请求视角章节的结果；通过组合 Schema 清单与实例目录视角可获得平台的元模型与实例可视清单。

**Acceptance Scenarios**:

1. **Given** Agent 指定一组视角子集与目标 Bundle/实体，**When** 发起组合查询，**Then** 返回恰好包含所请求视角章节的聚合结果
2. **Given** 请求同时包含 Schema 清单与实例目录视角，**When** 查询，**Then** 返回平台元模型定义与实例的可视清单（承接原独立"库范围"查询的诉求）
3. **Given** 指定的视角子集包含影响追溯视角，**When** 查询，**Then** 返回正向影响、反向依赖与影响路径分层

---

### User Story 6 - Agent 影响感知评估变更风险 (Priority: P3)

变更实施前，Agent 需要评估"这个变更会波及谁、谁依赖它"。Agent 发起含影响追溯内容的查询，系统返回正向影响、反向依赖与影响路径详情，支撑变更评估与风险预判。

**Why this priority**: 影响感知是进阶认知能力，帮助 Agent 在变更前预判风险范围，价值高但依赖前置认知建立，优先级后置。

**Independent Test**: 可独立验证——Agent 发起含影响追溯视角的查询，系统返回按影响范围分层的正向影响、反向依赖与影响路径详情。

**Acceptance Scenarios**:

1. **Given** 请求包含影响追溯视角，**When** Agent 查询某实体的影响，**Then** 返回正向影响、反向依赖与影响路径详情
2. **Given** 影响范围存在多层，**When** 结果返回，**Then** 按影响程度分层呈现，便于 Agent 区分直接与间接影响

---

### User Story 7 - 领域知识工程师验证认知新鲜度 (Priority: P3)

领域知识工程师需要确认"这份认知还是最新的吗"。每次查询结果都附带各 Bundle 已发布版本号与查询时间戳（版本锚），工程师对比前后两次查询的版本锚即可判断认知是否过期。

**Why this priority**: 新鲜度保障是认知可信度的基础，跨所有能力生效；作为校验性质的能力，优先级后置但仍为必交付能力。

**Independent Test**: 可独立验证——每次查询结果均包含版本锚；将前后两次查询的版本锚对比，若某 Bundle 版本发生变化则提示认知可能已过期。

**Acceptance Scenarios**:

1. **Given** 任意一次成功查询，**Then** 输出中包含各 Bundle 已发布版本号与查询时间戳组成的版本锚
2. **Given** 前后两次查询对比发现某 Bundle 版本发生变化，**When** 工程师进行对比，**Then** 提示"认知可能已过期，建议重新获取"
3. **Given** 两次查询对比版本锚一致，**When** 工程师进行对比，**Then** 不产生过期误报

---

### Edge Cases

- 服务端不可达或网络异常：给出人类可读中文提示（含服务地址），不暴露技术堆栈
- 服务端返回模板不存在、范围非法、归属失败等失败码：映射为对应中文提示，归属失败时展示候选
- 部分认知视角查询超时被截断或范围不匹配被跳过：以提示形式展示，避免 Agent 误认为数据缺失
- 自然语言描述存在多个候选或零命中：多候选请用户选择，零命中终止并说明原因与现有可选项
- 用户补充描述后重新推测：支持在失败后基于补充信息重新发起推测
- 结果集翻页到末尾：正常结束，不报错
- 服务端新增或变更模板：能力与命令清单自动跟随，不因清单硬编码而失效
- 未配置任何配置项：按默认值即可正常运行（零配置可用）
- 未知模板标识：给出中文提示，指导用户从服务端实际注册清单中选择

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供全部 8 项元认知指导能力：平台发现、领域导航、任务认知、实体即时指导、子任务认知（收窄）、自由视角组合查询、影响感知、认知新鲜度；每项能力必须有明确的"指导的问题"与"指导的行为"
- **FR-002**: 系统能力必须由服务端模板注册表驱动，不得硬编码模板清单；服务端新增或变更模板时，消费端能力与命令清单须自动跟随
- **FR-003**: 系统必须支持按需组合任意认知视角子集进行查询，不限于预置模板的视角组合
- **FR-004**: 系统必须支持指定认知深度（L1/L2/L3）、代理原型（执行/探索/审计/编排）与 Token 预算，交由服务端完成适配
- **FR-005**: 系统必须支持实体级认知入口（指定实体时返回该实体维度的认知）与子任务收窄模式（继承/纯净）两种能力入口
- **FR-006**: 系统必须能交付影响追溯输出（正向影响、反向依赖、影响路径详情），支撑变更评估与风险预判
- **FR-007**: 系统必须在每次输出中保留各 Bundle 已发布版本号与查询时间戳组成的版本锚；应支持对比前后两次查询判定认知是否过期并提示
- **FR-008**: 系统必须支持两种输出格式——结构化格式（默认）与可读说明格式（Markdown），两者语义内容完全一致，且可无需二次解析直接注入 Agent 上下文
- **FR-009**: 系统默认须原样呈现服务端返回结果，不主动改写语义内容，保证零信息损耗
- **FR-010**: 系统必须负责将 Agent 的自然语言意图转换为结构化参数，不得向服务端发送任何自然语言文本
- **FR-011**: 系统推测 Bundle/主题域/实体标识（FQN）时，必须基于服务端认知接口返回的目录与实例数据匹配，严禁凭空捏造或臆测
- **FR-012**: 系统标识匹配须按确定性优先级（精确标识 > 名称 > 关键词/别名 > 子串）执行；唯一命中自动确认继续，多候选列出请用户选择，零命中终止并说明原因与平台现有可选项
- **FR-013**: 系统应为高频能力提供便捷入口命令（统一命名空间前缀 + 点号命名）；命令是能力的投影，能力存在即命令可选，不要求每能力必有命令
- **FR-014**: 任务认知须要求指定 Bundle；实体即时指导须要求指定实体；子任务认知须要求指定 Bundle 与入口实体；领域导航须要求指定 Bundle；缺失时输出用法提示并中止执行
- **FR-015**: 所有命令必须无状态、可重复执行，不保存任何会话或任务上下文；相同参数连续执行结果语义一致（时间戳、版本锚等动态字段除外）
- **FR-016**: 列表型输出须支持指定页大小与游标续翻，可完整遍历全部结果
- **FR-017**: 系统应为能力提供自包含的 Skill 定义（含参数说明、调用示例、输出格式说明），挂载后无需二次开发即可调用；Skill 须经命令通道执行，不直接承载与服务端的通信细节
- **FR-018**: 系统必须将各类失败情形（模板不存在、范围非法、范围为空、实体归属失败、部分视角超时、上游不可用、网络不可达）映射为人类可读的简体中文提示，不得暴露原始技术细节
- **FR-019**: 系统须将部分视角超时截断与范围不匹配跳过以提示形式展示，避免 Agent 误判为数据缺失
- **FR-025**: 系统对瞬时故障（网络错误、上游不可用、部分视角超时）自动重试 1 次，重试后仍失败则给出人类可读中文提示
- **FR-020**: 系统必须支持配置（配置文件或环境变量）服务端地址、超时、默认深度、默认原型、默认 Token 预算；未配置任何项时采用默认值即可运行（零配置可用）；配置覆盖优先级固定为命令参数 > 环境变量 > 配置文件 > 默认值；配置文件位于用户目录（`~/.config/metaforge/config.yml`），环境变量命名统一采用 `META_FORGE_` 前缀
- **FR-021**: 系统必须支持链路追踪标识透传与详细模式输出（展示原始请求/响应），便于排障
- **FR-022**: 系统必须在项目根维护开发态环境（与既有开发态目录共存、职责分离），提供项目根定位、环境信息摘要、认知查询调用、内置模板清单、标识推测、健康检查等开发操作入口；系统与服务端的所有通信细节必须集中封装承载，命令与 Skill 交付层不得直接暴露接口地址、协议或调用细节，以保证凭据安全与可维护性
- **FR-023**: 系统必须原样透传与服务端对齐的认知请求字段，不做语义改写
- **FR-024**: MVP 阶段系统不对服务端实施传输层认证，直接建立连接发起查询；任何情况下系统不得在文件或代码中硬编码凭据（如令牌、口令）

### Key Entities *(include if feature involves data)*

> 本产品不持有任何业务数据主权，以下为命令与 Skill 层的逻辑实体，非持久化模型。

- **元认知指导能力（CognitionCapability）**: 8 项能力的集合（平台发现/领域导航/任务认知/实体即时指导/子任务认知/自由视角组合/影响感知/认知新鲜度），是需求主体
- **模板定义（TemplateDefinition）**: 服务端模板注册表中的条目，消费端从中解析可用模板，驱动能力与命令投影
- **命令定义（CommandDefinition）**: 能力在 opencode 的交付投影，含命名空间命令标识、绑定模板、参数→请求字段映射、用法说明与默认值；数量不设固定上限
- **Skill 定义（SkillDefinition）**: 自包含能力单元，含参数说明、调用示例与输出格式说明；经命令通道执行
- **认知请求（CognitionRequest）**: 与服务端对齐的结构化查询参数（范围、实体、深度、原型、Token 预算、视角子集、格式等）
- **认知响应（CognitionResponse）**: 服务端返回的认知简报，含元信息（版本锚、截断/跳过说明）与各视角章节
- **版本锚（DataVersionAnchor）**: 各 Bundle 已发布版本号 + 查询时间戳，用于认知过期判定
- **标识候选（FqnCandidate）**: 标识推测的中间产物（标识/名称/说明/所属类型/匹配方式），用于唯一命中确认或多候选选择
- **开发态环境（DevEnvironment）**: 开发操作入口（项目根定位、环境摘要、认知查询、模板清单、标识推测、健康检查），是全部服务端通信细节的唯一承载处

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Agent 从自然语言描述到获得可直接使用的任务认知简报，端到端交互不超过 3 个往返，无需人工二次修正查询参数
- **SC-002**: 查询输出可直接注入 Agent 上下文、无需二次解析的适用率达到 100%
- **SC-003**: 描述明确的场景下，标识推测唯一命中自动确认的准确率达到 95% 以上；系统臆造不存在的标识的比例为 0%
- **SC-004**: 多候选场景 100% 列出候选供选择；零命中场景 100% 终止执行并给出原因与平台现有可选项
- **SC-005**: 全部失败场景（服务不可达、模板无效、参数缺失、归属失败等）100% 呈现为人类可读中文提示，原始技术细节暴露率为 0%
- **SC-006**: 每次成功查询均携带版本锚；版本发生变化后，工程师可在一次对比内判定认知过期
- **SC-007**: 服务端新增或变更模板后，消费端能力与命令清单无需人工改动即自动跟随（以模板注册表动态解析为准）
- **SC-008**: 零配置安装后即可调用本地服务端完成一次完整认知查询（可独立演示）
- **SC-009**: 相同参数连续两次执行结果语义一致（时间戳、版本锚除外），可安全重复执行
- **SC-010**: 8 项能力均有至少一种交付形态（命令或 Skill）可独立演示，且不出现任何直接暴露服务端通信细节的文件
- **SC-011**: 任务认知与实体即时指导的端到端耗时分别不超过 500ms 与 150ms（引用服务端预算）；CLI 侧开销占端到端耗时比例 <5%

## Assumptions

- Agent 运行于 opencode CLI 环境，以 AI slash 命令 + Skill 形态交付，不提供 Web UI（与全局规划一致）
- 服务端（agent-cognition BC）已部署且认知查询接口可用；服务端返回的语义内容为唯一权威，本产品仅负责请求构造、传输、响应解析与呈现，不持有业务数据（遵循纯消费端边界）
- 服务端访问采用无认证直连（MVP，见 FR-024）；凭据不落盘、不硬编码
- 字段命名与响应结构以服务端实际实现为准；契约文档与实现存在命名差异时，MVP 按实际实现处理，并已列入与上游核对的风险项
- 版本锚对比由调用方（Agent/工程师）携带前后两次数据完成，本产品不保存任何状态（遵循无状态幂等原则）
- MVP 阶段不实现 MCP 委托发布与导入授权/白名单过滤；授权与权限过滤由上游服务端强制执行，本产品仅透传请求，不构成对全局 MUST 级权限原则的弱化
- 业务语义与真实业务 Bundle 数据可能尚未完全上料，验收阶段先用模拟数据验证消费链路（对应用户可直接验证的既有风险）
- 用户可见提示使用简体中文，术语（Bundle、FQN、Skill、MCP、REST 等）保留英文原文

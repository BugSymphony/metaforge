# MetaForge

**GitHub Description（一句话）**

> 元数据驱动的 AI 语义基础设施，赋予 AI Agent 真正的**元认知**——对自己的认知与行为"有所知、有所畏、有所止"。

**完整描述（README）**

> **MetaForge —— 让 AI Agent 拥有元认知**
>
> 认知是"知道世界是什么"，**元认知**是"知道自己知道什么、不知道什么、能做什么、不能做什么"。
>
> 现在的 Agent 只拥有"认知"——大模型泛化出的知识，却没有"元认知"——对自身认知边界与行为边界的觉察。于是业务落地时"不懂业务、乱执行、边界失控"。
>
> MetaForge 以元数据构建 Agent 的**外部元认知系统**：把业务世界的"元认知说明书"（概念、关系、规则、能力边界）结构化沉淀，作为 Agent 认知自我的镜子。通过三大能力实现：
>
> - **元模型定义 —— 认知的锚**：为"我知道什么"建立唯一、无歧义的元认知基准，让 Agent 的认知有据可依、可被校准。
> - **元数据治理 —— 认知的界**：版本管控 + 显式导入授权 + 白名单过滤，让 Agent 时刻知道自己认知的边界在哪里，看不见的即不存在。
> - **元认知推理引擎 —— 认知的用**：图查询与规则推理，让 Agent 在授权范围内自知而行——先照镜子，再行动，每一步都在元认知的约束之内。这面镜子不仅能照"现在"，还能推演"因果"：
>   - **变更影响分析**：改一个概念、一个字段或一条规则，沿关系网络正向扩散——看清"会波及哪里"；反向依赖溯源——看清"谁在依赖它"。动手之前，先看清影响半径。
>   - **按需信息供给**：执行某个业务步骤，只注入它真正需要的输入与上下文，不多带、不漏带——既省 Token，也不让无关信息干扰决策。
>   - **路径推演与决策点识别**：从当前节点走到目标，要经过哪些环节、哪里有分支决策、还缺哪些信息——先把路走一遍，再让 Agent 迈步。
>
> **当 Agent 拥有元认知：**
> 它知道自己懂什么，于是不臆测；知道自己会什么，于是不越界；知道自己遵循什么规则，于是不乱来。
>
> 认知清晰，行为有界——这才是 Agent 落地的根基。
>
> **技术栈**：Java 21 · Spring Boot 3.4 · Spring AI · PostgreSQL · JSON Schema 2020-12 · REST + MCP

# 如何改变 AI Agent

AI Agent 的落地难题，根源是"懂不懂业务"。MetaForge 用一套语义说明书 + 六大认知模板，从认知、决策、执行、协作、纵深五个维度重塑 Agent。

## AI Agent 落地的真问题

大语言模型天生善于"生成"，却未必"懂业务"。当 Agent 面对一个具体业务场景时：

1. **不懂业务**：模型训练先验里没有你的业务——虚构的流程、阈值、对象结构，模型一无所知。实测中，让一个 Agent 描述"设备健康巡检任务"的流程与阈值，它只能回答"不知道"。
2. **乱执行**：没有明确的规则与边界约束，Agent 可能越权、超范围、凭猜测执行。
3. **无边界**：上下文全量注入导致冗余低效，Agent 分不清"哪些是我该知道的"。

传统方案各有短板：RAG 给碎片化文本、向量库给相似片段、规则引擎把规则焊死在代码里——都难以让 Agent"有据可依"地懂业务。

## 五维转变

| 维度 | 无 MetaForge | 有 MetaForge |
|------|-------------|--------------|
| **认知来源** | 训练先验（可能过时、缺失、幻觉） | 实时查询语义说明书（权威、可更新） |
| **业务规则** | 散落代码/文档/人脑 | 集中建模、阈值语义化、可查询 |
| **决策方式** | LLM 猜测 | 说明书规则对照（"800 > 500 → 转复核"，有据可依） |
| **可解释性** | 黑盒 | 每步决策可溯源到说明书规则 |
| **执行边界** | 单 Agent 自由发挥 | DELEGATE 委派，子 Agent 只接触职责内认知 |
| **业务纵深** | 通用对话 | 精通医疗/工业/数据中心/供应链等垂直业务 |

## 核心转变：从"会聊天"到"懂业务"

**MetaForge 让 Agent 从"会聊天的模型"进化为"懂业务的执行者"**：

- 知识不再靠猜测，而来自**可查询、可解释、可更新的语义说明书**
- 决策不再靠感觉，而来自**说明书规则对照具体数据**
- 协作不再无边界，而通过 **DELEGATE 收窄认知边界**（子 Agent 只接触职责内内容）
- 业务不再隔层纱，而通过**垂直语义库**精通特定领域

## 价值总结

1. **可控**：Agent 的业务认知受语义说明书（结构化元数据）约束，不越界、不臆造，执行结果可预期
2. **可解释**：每一步决策可溯源到说明书规则（"为什么转复核？因为 800mg > 500mg 阈值"）
3. **可复用**：一套元数据语义库服务多个 Agent 与场景，避免重复建设（如同数据库被多个应用共享）
4. **可治理**：语义即元数据、元数据随版本统一迭代，规则变更可管控、可追溯，Agent 升级与语义演进解耦

MetaForge 的价值底座是**元数据**——因为"语义以元数据形态沉淀"，才能被统一建模、版本治理、跨 Agent 复用，最终让 Agent 的认知可控、可信、可持续演进。

## 一句话

> 数据是流水，说明书是航道——MetaForge 管航道，Agent 沿着航道稳稳执行业务。

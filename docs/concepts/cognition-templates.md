# 六大认知模板与八维度认知模型

语义说明书（结构化元数据）是"内容"，认知模板是"消费方式"——Agent 通过六大认知模板，在恰当的时刻从元数据层获取恰当维度的认知。

## 模板 = Agent 的决策时刻

MetaForge 提供六个认知模板，每个对应 Agent 生命周期中的一个决策时刻：

| 模板 | 名称 | Agent 的决策时刻 | 回答的问题 |
|------|------|-----------------|-----------|
| DISCOVER | 元模型发现 | 初入平台 | 平台上有哪些语义库/类型/关系？ |
| ORIENT | 业务域定位 | 需要定位 | 我在哪个业务域？该域下有什么任务/对象？ |
| BRIEF | 实体/任务全景 | 接任务前 | 这个任务/实体全貌是什么？流程/规则/能力？ |
| GUIDE | 单步执行指南 | 执行某一步 | 这一步怎么做？决策分支、约束、工具？ |
| FORECAST | 变更影响链路 | 变更前 | 改动会波及谁？风险多大？要回归哪些？ |
| DELEGATE | 子任务委派 | 委派子任务 | 子 Agent 该知道什么？认知边界如何收窄？ |

六个模板串起来，正是 Agent 从"了解平台 → 定位域 → 理解任务 → 执行步骤 → 评估变更 → 委派协作"的完整认知链路。

## 模板 = 算子编排

每个模板不是写死的逻辑，而是**一组认知算子的编排**：

```
模板 GUIDE（单步执行指南）
  = 实体画像(entity-profile)      → 这是什么
  + 规则清单(rule-listing)        → 有什么约束
  + 工具发现(tool-discovery)      → 用什么能力
  + 前后步导航(adjacent-step)     → 上一步/下一步
  + 决策分支(decision-branch)     → 怎么决策、分支去向
  + 直连关系(direct-link)         → 与谁直接关联
```

- **算子**是最小认知单元（一次查询、一个回答）
- **模板**是按场景编排的算子组合
- 调用方可传 `selectOperators` **自由裁剪算子子集**——"只要画像和规则，不要流程"等按需组合

模板驱动 + 算子自由组合，让一套语义底座灵活适配各种具体诉求。

## 八维度认知语义模型

算子不是随意堆叠，而是按**八个认知维度**体系化组织，分三层递进：

| 维度 | 层 | 回答的问题 | 代表算子 |
|------|-----|-----------|---------|
| 本体论 ONTOLOGICAL | object | 是什么 | 实体画像、元模型发现 |
| 结构论 STRUCTURAL | object | 由什么组成 | 组成结构、归属 |
| 关系论 RELATIONAL | object | 与谁关联 | 直连、邻域、影响追溯 |
| 流程论 PROCEDURAL | object | 顺序怎么走 | 流程蓝图、决策分支、前后步 |
| 约束论 DEONTIC | action | 该不该做 | 规则清单、约束冲突 |
| 能力论 CAPABILITY | action | 用什么做 | 工具发现、协议细节 |
| 认知论 EPISTEMIC | meta | 认知新鲜吗 | 新鲜度检查 |
| 治理 GOVERNANCE | meta | 边界在哪 | 范围收窄（委派） |

三层递进：**object（对象是什么）→ action（动作怎么做）→ meta（元认知）**。

这套模型的意义：**一套语义模型，覆盖 Agent 的所有认知维度**——从"对象是什么"到"动作该不该做"到"认知是否新鲜"，认知需求被完整、不碎片地建模；新增能力按维度挂载，可扩展、不失控。

## 认知深度与原型

- **认知深度** L1（概览）/ L2（标准）/ L3（全量）：决定保留多少算子、多详细
- **Agent 原型** execution / exploration / audit / orchestration：决定该模板下哪些算子对当前 Agent 可用

深度与原型配合，让 Agent 的每一次认知获取"恰到好处"——不多不少、不冗余。

## 自由组合的价值

- 预置模板覆盖高频场景，开箱即用
- `selectOperators` 支持按需裁剪，长尾诉求也能精确满足
- 模板是场景的投影，算子是能力的原子——**场景可增、能力可扩、彼此解耦**
